# 多实例限流并发修复

日期：2026-07-29

## 修复范围

本次仅修复模型请求限流和批量创建 API Key 审计确认的问题：

- 分组限流配置改为写锁更新，并通过同一快照读取开关、窗口和请求上限。
- Redis 成功请求限制改为按请求 ID 原子预留；失败响应释放预留，避免多实例同时越过上限。
- 成功请求计数使用 `v2` Redis Key，避免滚动发布时与旧 LIST 类型冲突。
- 通用 Redis 令牌桶在 Redis 重启或脚本清空后自动使用 `EVAL` 恢复脚本。
- 批量创建部分成功时不再让身份验证弹窗遮挡一次性密钥，也不会自动重放已部分成功的批次。
- 管理页面明确说明：分组配置用于选择每个用户的上限，计数仍按用户独立累计。

## 限流作用域

“模型请求速率限制”按用户 ID 计数。API Key 分组优先选择对应上限；Key 未设置分组时使用用户分组。一个用户的多个 API Key 共用该用户计数。

“API Key 安全策略”中的持续 RPS 和并发限制按单个 API Key 计数。管理员可以创建“指定用户”策略，但该策略是给该用户的每个 Key 应用相同的单 Key 上限，不是所有 Key 的合计上限。

当前没有单独覆盖某个用户的“全部 Key 合计速率”配置。需要用户总上限时，可先使用独立用户分组；若同组用户仍需不同上限，应另行增加用户级覆盖配置。

## 多实例说明

- Redis Lua 脚本负责跨实例原子限流，不依赖单机内存锁。
- PostgreSQL 计费仍由事务、条件更新和行锁保证一致性；热点用户可能排队，但不会因实例数量增加而绕过额度更新。
- Redis 未启用时，内存限流只在单个实例内生效，不适用于多实例统一限流。
- 系统配置由各实例定时从数据库同步，修改后在一个同步周期内可能短暂存在新旧配置并存。
