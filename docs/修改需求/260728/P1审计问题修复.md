# 账号与 API 令牌安全改造 P1 审计问题修复

日期：2026-07-28

## 修复范围

本次仅修复安全审计确认的四个 P1 问题，没有调整其他令牌策略、页面布局或业务接口。

1. 模型风控 Redis 故障处理
   - 模型窗口 Redis 命令失败时遵守令牌的 `fail_closed` 配置。
   - `fail_closed=false` 时记录降级日志并放行。
   - `fail_closed=true` 时返回安全服务暂不可用。

2. 五分钟不同模型滑动窗口
   - 将会持续累积成员的 Redis Set 改为按时间戳计分的 ZSET。
   - 每次检查原子清理五分钟前的数据、更新当前模型时间并统计有效成员。
   - 持续流量不会再延长旧模型记录的有效期。

3. 密码安全更新事务
   - 仅在修改密码时为 `User.Update` 和 `User.Edit` 建立数据库事务。
   - 密码、账号 Access Token、`security_version`、OAuth Grant 以及同请求内的用户资料更新共同提交或回滚。
   - 不修改密码的普通资料更新继续沿用原调用方式。

4. Default 前端策略字段保留
   - 编辑令牌时加载并保留 `max_quota_per_request`、`hourly_quota`、`daily_quota`。
   - 提交时不再把已有额度安全限制静默覆盖为零。
   - 本次不新增额度输入控件，只修复已有策略的完整往返。

## 复审补充

第二次审计发现，编辑抽屉在令牌策略仍在加载或加载失败时仍可提交默认值。现已增加：

- 编辑数据加载状态和提交就绪状态；
- 令牌与安全策略均成功加载前禁用保存；
- 任一加载请求失败时提示错误并保持禁止提交；
- effect 清理标记，避免关闭抽屉或切换令牌后由旧请求覆盖当前表单；
- 提交函数内的二次就绪校验，避免绕过按钮状态提交。

补充验证：

## 第三次审计补充

第三次审计确认并修复：

- 实际结算额度超过单次、小时或每日限制时，记录超限并立即暂停对应令牌，阻止后续继续消费；
- 即使只配置单次额度限制，也会保留结算检查状态，不再因没有窗口预算而跳过实际额度检查；
- 令牌资料与 `security_policy` 改由同一个更新接口、同一个数据库事务提交；
- Default 前端移除第二次策略更新请求，避免令牌资料成功而策略失败的部分提交。

新增回归覆盖：

- 实际消费高于预估且超过单次上限时，令牌自动变为禁用；
- 令牌资料与安全策略能够通过联合更新边界共同提交；
- SQLite 下按令牌 ID 暂停时正确读取保留字 `key` 列。

## 第四次审计补充

第四次审计确认并修复：

- 实际结算修正 Redis 失败时继承预留阶段的 `fail_closed`，开启后立即暂停对应令牌；
- 风险暂停先把缓存令牌标记为禁用，再尝试删除；删除失败时禁用标记继续阻止缓存认证；
- 令牌与策略事务提交后改为缓存写入、删除和安全禁用降级，不再把已经提交的数据库更新错误报告为失败；
- 安全策略缓存优先写入最新策略，失败时删除旧缓存；仍无法恢复时临时禁用对应令牌缓存。

新增回归覆盖：

- 结算阶段 Redis 失败且启用 `fail_closed` 时自动禁用令牌；
- 数据库联合更新已提交但 Redis 不可用时，接口边界不再返回虚假的事务失败。

## 第五次审计补充

第五次审计确认并修复：

- 预扣成功后 Redis 被关闭或客户端不可用时，结算阶段仍执行 `fail_closed` 并暂停对应令牌；
- 独立安全策略更新和删除接口复用提交后缓存恢复逻辑；
- 独立接口的数据库修改已经提交时，不再因缓存失败向客户端返回虚假的事务失败；
- 策略缓存无法更新或删除时，继续使用临时禁用令牌缓存作为安全降级。

新增回归覆盖：

- 结算时 Redis 客户端变为不可用且启用 `fail_closed` 时自动禁用令牌；
- 独立策略更新和删除在数据库提交后遭遇 Redis 故障时仍返回成功，并保持数据库结果正确。

## 第六次审计补充

第六次审计修复结算退款的误暂停边界：

- 只有实际消费高于预扣额度，且追加额度无法写入 Redis 时才执行 `fail_closed`；
- 实际消费低于预扣额度时，退款修正失败只会保守地多计窗口额度，不再暂停令牌。

新增回归覆盖：退款修正期间 Redis 不可用且启用 `fail_closed` 时，令牌保持启用。

## 第七次审计补充

第七次审计修复预扣失败后的窗口额度漏记：

- 预算预留记录明确保存窗口额度是否已成功写入 Redis；
- fail-open 模式下预扣脚本报错仍保留结算对象，不再跳过实际消费结算；
- 已成功预扣时按实际额度与预扣额度的差额结算；
- 未成功预扣时按完整实际额度结算，避免少计或产生负数窗口额度；
- 结算阶段首次创建的小时、每日额度键同步设置过期时间。

新增回归覆盖：未完成预扣时，即使实际额度低于预估额度，结算仍按完整实际额度执行 `fail_closed`。

## 多实例并发租约补充

针对多实例滚动发布和实例异常退出，令牌并发限制完成以下调整：

- 共享整数计数器改为按请求 ID 保存的 Redis ZSET 租约；
- 获取并发槽位时原子清理超过 30 分钟的失效租约；
- 请求完成时只删除当前请求自己的租约；
- 单个实例崩溃或被强制重启后，遗留并发槽位会独立过期，不会被其他请求续期；
- 使用 `concurrency:v2` 新键避免滚动发布期间与旧整数键发生 Redis 类型冲突。

滚动发布期间旧实例和新实例会短暂使用两套并发计数，应尽快完成实例替换；全部实例升级后只使用 v2 租约。

长请求租约补充：

- 活动请求每 10 分钟续租一次，将自己的租约有效期重新延长至 30 分钟；
- Redis 短暂重启导致租约丢失时，仍在运行的请求会在下一次续租时恢复自己的成员；
- 请求释放时先停止并等待当前续租结束，再删除租约，避免释放与续租竞争导致成员复活；
- 即使释放时 Redis 不可用，也会停止本地续租协程，Redis 中的成员随后按原有效期自动清理。
