# API Key 用户级共享限额与 RPM 增强

## 修改目标

在保留现有单 API Key 安全策略的基础上，补充用户级共享保护，避免同一用户通过创建或轮换多把 Key 绕过请求速率、并发数和小时/每日额度限制。同时增加 RPM 配置，适配普通用户每分钟仅少量请求的使用场景。

本次仅修改 Token 安全策略直接链路，不调整全局默认策略、不修改用户 Key 数量上限、不改变 OAuth 权限和 Key 明文迁移流程。

## 新增配置

管理员安全策略新增以下字段，`0` 均表示不启用该限制：

| 字段 | 含义 |
| --- | --- |
| `sustained_rpm` | 单 Key 持续每分钟请求数；配置后优先于 `sustained_rps` |
| `user_sustained_rpm` | 同一用户全部 Key 共享的持续每分钟请求数 |
| `user_burst_capacity` | 同一用户全部 Key 共享的突发容量 |
| `user_max_concurrency` | 同一用户全部 Key 共享的最大并发数 |
| `user_hourly_quota` | 同一用户全部 Key 共享的每小时额度 |
| `user_daily_quota` | 同一用户全部 Key 共享的每日额度 |

用户级字段只允许管理员配置。普通用户更新单 Key 策略时不能写入或覆盖这些字段。

## 执行语义

- RPM 和 RPS 使用同一套连续补充的令牌桶。单 Key 配置了 RPM 时，RPM 优先，RPS 自动归零。
- `burst_capacity` 同时作为单 Key RPM/RPS 的桶容量；启用 RPM 但容量小于 `1` 时自动归一为 `1`。
- 用户级 RPM、并发和额度以用户 ID 为共享作用域，同一用户的所有 Key 使用同一计数。
- 请求必须同时通过用户级限制和单 Key 限制；任一限制拒绝，请求均在计费前返回 `429`。
- 用户级和单 Key 额度预留共用同一套预留、结算与回滚流程。后续窗口预留失败时，会回滚此前已成功的窗口，避免失败请求占用额度。
- 当风险响应为“自动暂停令牌”时，超限会暂停本次请求使用的 Key。用户共享计数仍会阻止该用户使用其他 Key 继续绕过共享额度，但不会批量停用该用户的其他 Key。
- Redis 不可用时继续沿用现有 `fail_closed` 行为，本次没有改变降级策略。

## 兼容性与灰度发布

新增数据库字段默认均为 `0`，因此只部署代码不会给存量或新建 Key 自动增加限制，原有 RPS、并发、单次/小时/每日额度行为保持不变。

新增管理员字段只持久化在规模较小的安全策略表中；单 Key 策略模型中的对应有效值不写入数据库，避免本次上线为大规模单 Key 策略表增加无用列。

滚动发布必须按以下顺序执行：

1. 先更新固定的 master 节点，使数据库自动迁移完成。
2. 逐台更新 slave 节点，期间保持所有新增字段为 `0`。
3. 确认所有旧版本实例已经退出流量。
4. 再创建或更新包含 RPM、用户共享限制的管理员策略。
5. 从低风险用户或分组开始灰度，观察 `429`、安全拒绝日志、Key 暂停记录和请求延迟后再扩大范围。

混合版本期间不能提前启用新增字段：旧实例会忽略新增字段，并可能把缺少新增字段的旧版策略缓存重新写入，导致限制在不同实例间不一致。

为兼容旧管理端和旧 API 客户端，更新已有策略时，未出现在请求 JSON 中的 RPM 和用户共享字段会保留数据库现值；明确传入 `0` 才会清除对应限制。创建新策略时，省略字段仍按 `0` 处理。

用户级和单 Key 并发租约会分别续期。单个租约因过期或被删除而丢失时，只停止该租约的续期，其余仍有效的租约继续续期；临时 Redis 错误则保留租约并在下一周期重试。

## 建议初始配置

普通低频用户可先从以下范围灰度，具体值应根据生产峰值调整：

- 单 Key RPM：`5`～`10`
- 单 Key 突发容量：`1`～`2`
- 用户共享 RPM：略高于单 Key RPM，例如 `10`
- 用户共享突发容量：`2`
- 用户共享并发：`2`～`4`
- 用户共享小时/每日额度：按可接受的盗刷最大损失设置，不应直接照搬单 Key 额度乘以 Key 数量
- 风险响应：先“通知”观察误杀，再对已验证策略启用“自动暂停令牌”

平台默认策略会完整作用于没有更具体用户/分组策略的存量 Key。上线时仍应先配置高流量用户策略，最后再决定是否启用平台默认策略。

## 已知边界

- 小时和每日额度仍使用 UTC 固定窗口，并非滑动窗口。用户级共享额度已经关闭多 Key 绕过，但整点或零点附近仍可能在相邻窗口各使用一次完整额度。
- RPM 令牌桶是连续速率限制，不等同于日志页面按自然分钟汇总的 RPM 指标。
- 本次没有新增用户级“不同模型数”共享限制，也没有自动调整 Key 数量上限或强制 Key 到期时间。

## 验证范围

- Go：模型和 DTO 校验、策略合并、RPM 换算、用户共享额度作用域、并发租约兼容、预算预留/结算/回滚相关测试。
- 前端：TypeScript 类型检查、策略合并测试、管理员安全策略表单测试。
- i18n：`en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、`vi` 已同步，i18n 同步检查通过。
- Redis 脚本集成用例已覆盖用户共享额度、RPM 和并发，但当前开发环境未配置 `TOKEN_SECURITY_REDIS_TEST_URL`，因此该用例在本地跳过，需在预发布环境执行。

生产灰度仍需验证：

- 同一用户两把不同 Key 是否共享 RPM、并发、小时和每日额度；
- 成功、上游失败和客户端中断时，预留额度是否按实际消费结算；
- 用户共享超限时是否记录安全拒绝日志，且“自动暂停令牌”只暂停当前 Key；
- 全部实例升级后再启用新增字段，确认不同节点返回结果一致。
