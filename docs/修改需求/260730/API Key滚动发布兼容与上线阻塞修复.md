# API Key 滚动发布兼容与上线阻塞修复

日期：2026-07-30

## 背景

生产环境正在持续提供服务，只允许滚动发布。原实现会在新实例启动迁移时把 `tokens.key` 原地改写为 `h:<hash>`，而旧实例只按明文 `key` 查询。新实例随后还会清理 Redis 令牌缓存，旧实例回源数据库后将无法认证已经迁移的 Key。

生产环境已经固定并统一配置 `CRYPTO_SECRET`，因此不同实例计算出的 `key_hash` 和 Redis 缓存键保持一致。本次只修复代码兼容和已确认的上线问题，不调整生产限流策略。

## 修改内容

### 1. 滚动发布兼容阶段

- 启动迁移改为非破坏性元数据回填：
  - 填充 `key_hash`；
  - 填充 `key_hint`；
  - 保留明文 `tokens.key`，供旧实例继续认证。
- 新建和轮换 API Key 在兼容阶段同时写入明文 `key`、`key_hash` 和 `key_hint`。
- 新实例继续支持 `key_hash` 与明文 `key` 双读。
- 增加回归测试，覆盖存量 Key 回填、新建 Key 和轮换 Key 在混部期间均可被旧实例读取。

本版本是第一阶段兼容桥接版本，不执行明文清理。只有确认所有运行实例都已升级到本版本或更新版本后，才能在后续版本执行最终哈希存储迁移。

### 2. 已确认的 P2 上线问题

- 删除无调用方且缺少用户归属校验的 `model.DeleteTokenSecurityPolicy`。
- 普通用户通知改为持有通知许可；SMTP、Webhook、Bark 或 Gotify 发送失败时释放本次许可，避免短暂故障耗尽通知额度。
- Token 安全告警的异步通知许可只在实际发送成功后计入额度；加载用户、渠道校验或发送失败时释放许可。
- Redis 通知许可释放脚本读取返回值；窗口已变化导致未释放时，在 debug 模式记录诊断日志。
- 令牌限速、并发租约和模型风险 Lua 脚本提升为包级脚本实例，避免每次请求重新创建并计算脚本摘要。
- 补齐以下操作日志标签，并同步 default/classic 两套前端语言包：
  - `auth.logout_all`
  - `token.rotate`
  - `token.risk_detected`
  - `token.security_profile_update`
  - `token.security_profile_delete`
- 删除 OAuth 委托令牌文档中已经移除的创建、完整 Key 查看和批量完整 Key 查看接口，并明确这些操作只能在控制台完成安全验证后执行。

## 无停机发布顺序

1. 备份 `tokens` 表，并确认所有实例使用完全相同且固定的 `CRYPTO_SECRET`。
2. 在应用发布前在线增加 `tokens.key_hash`、`tokens.key_hint` 及 `key_hash` 索引。应使用当前数据库支持的在线 DDL；不要依赖新 slave 实例先于 master 自动建表。
3. 先发布一个兼容版本实例，验证旧 Key、新建 Key、轮换 Key和 Redis 缓存未命中请求。
4. 逐个滚动其余实例，监控 401、数据库回源、Redis 延迟和连接池等待。
5. 通过系统实例列表和部署平台确认所有旧版本实例均已退出；实例离线判定窗口为 90 秒。
6. 再启动一次 master 兼容实例，使混部期间由旧实例创建的 Key 补齐 `key_hash` 和 `key_hint`。
7. 确认有效 Key 中 `key_hash IS NULL` 的数量为 0。

## 回滚边界

- 本兼容版本保留明文 `tokens.key`，可以滚动回退到发布前版本。
- 后续一旦执行最终明文清理，只能回滚到本兼容版本或更新版本，不能回滚到仅支持明文查询的旧版本。
- 最终明文清理不得绑定普通应用启动；必须作为单独、可观察、可重复执行的发布步骤。

## 验收要求

- 发布前存量 Key 在旧实例和兼容实例上均认证成功。
- 混部期间新建及轮换的 Key 在旧实例和兼容实例上均认证成功。
- Redis 缓存未命中时，旧实例仍可通过数据库明文列认证。
- 通知发送失败后，本次通知额度可以再次使用。
- 操作日志页面不再显示上述五个原始 action 字符串。
- OAuth 委托接口文档与实际路由一致。

## 尚未包含

- 本版本不执行 `tokens.key` 明文清理。
- 本版本不更改平台默认安全策略、RPS、并发、额度或风险响应配置。
- 真实生产数据库在线 DDL、混部定向流量和最终哈希清理仍需要按发布步骤单独验收。
